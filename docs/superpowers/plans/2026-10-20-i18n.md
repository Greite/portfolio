# Internationalisation FR / EN — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** servir tout le portfolio en `/fr` et `/en`, en statique, avec un contenu anglais complet et un SEO bilingue.

**Architecture :** toutes les routes passent sous `app/[lang]` (root layout dynamique, `generateStaticParams` fr/en). `proxy.ts` redirige en 307 les chemins sans préfixe selon `Accept-Language`. Les textes vivent dans des dictionnaires TypeScript (`en` typé par `fr`) lus côté serveur via `next/root-params` ; les composants client reçoivent leurs libellés en props.

**Tech Stack :** Next 16.4 (App Router, `proxy.ts`, `next/root-params`), React 19, TypeScript 7, Biome, bun. Aucune dépendance ajoutée.

**Spec :** `docs/superpowers/specs/2026-10-20-i18n-design.md`

## Global Constraints

- Aucune dépendance ajoutée à `package.json`.
- Langues : `fr`, `en` ; défaut et `x-default` : `en`.
- Redirections du proxy : **307**, `Vary: Accept-Language`, `Cache-Control: private, no-store`, query string conservée.
- Segment des pages projet : `/projects/<slug>` dans les deux langues ; slugs inchangés.
- Ancres de section (`#a-propos`, `#experience`, `#projets`, `#formations`) identiques dans les deux langues.
- `dictionaries/en.ts` est typé `Dictionary` (= `typeof fr`) : jamais de `as`, `Partial` ni `// @ts-…` pour contourner une clé manquante.
- Aucun dictionnaire complet importé par un composant client (`'use client'`) ; les imports `import type` sont permis.
- `next/root-params` jamais importé par un fichier utilisé côté client ou par `proxy.ts`.
- `seoTitle` ≤ 60 caractères, `description` 140 à 155 caractères, dans les deux langues.
- Anglais : adaptation idiomatique, pas de mot à mot ; même ton que le français.
- `bun run lint` est le seul contrôle de types (`ignoreBuildErrors: true`) : le lancer à chaque tâche.
- Commits : `Improve - #PRT-NoId - <description>` sur la branche `feat/i18n`.

## Écart assumé par rapport à la spec

La spec place la négociation dans `lib/accept-language.ts`. Le plan la met dans **`lib/locales.ts`**, qui contient aussi `locales`, `Locale`, `hasLocale` : ces éléments doivent être importables par le proxy et les composants client, alors que `lib/i18n.ts` importe `next/root-params` (interdit côté client). Le self-check devient `lib/locales.check.ts`. La tâche 1 met la spec à jour.

## Review Focus

1. Un chemin qui commence par `fr`/`en` sans être le segment exact (`/frontend`, `/english`) doit être redirigé (`/en/frontend`), pas laissé passer. → assert dans la tâche 1.
2. `Accept-Language` mal formé ou exotique (`FR-fr`, `fr;q=0`, `fr;q=abc`, `*`, chaîne vide) ne doit jamais lever ni donner autre chose que `fr`/`en`. → asserts dans la tâche 1.
3. Une capture `/projets/<slug>/<img>.webp` ne doit jamais être redirigée (le chemin contient l'ancien segment `projets`). → curl dans la tâche 2.
4. Le sélecteur de langue sur une page projet doit garder le slug (`/fr/projects/x` ↔ `/en/projects/x`). → assert sur `switchLocalePath` (tâche 1) + vérification navigateur (tâche 6).
5. Une URL préfixée inconnue (`/en/inconnu`, `/fr/projects/inconnu`) doit renvoyer une 404 **dans la langue de l'URL**, avec le style du site. → curl dans la tâche 2.
